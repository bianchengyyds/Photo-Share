# 管理员照片审核功能需求文档

## 一、功能概述

为管理员用户提供独立的照片管理界面，用于审核普通用户上传的照片。管理员可以查看所有用户上传的照片，并进行通过/拒绝操作。管理员自身不需要图片上传功能。

## 二、用户角色

| 角色 | 权限 |
|------|------|
| 普通用户 (USER) | 上传照片、管理自己的相册、查看自己的照片 |
| 管理员 (ADMIN) | 审核所有用户上传的照片、管理所有照片 |

## 三、数据库设计

### 3.1 照片表 (photo) 新增字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| status | VARCHAR(20) | 审核状态：pending(待审核)、approved(已通过)、rejected(已拒绝) |
| reviewed_by | VARCHAR(36) | 审核人ID（管理员ID） |
| reviewed_at | DATETIME | 审核时间 |
| reject_reason | VARCHAR(500) | 拒绝原因（可选） |

### 3.2 默认值

- 新上传的照片默认状态为 `pending`
- 管理员自己的照片自动设为 `approved`（管理员不需要审核自己的照片）

## 四、后端 API 设计

### 4.1 管理员专用接口

#### 4.1.1 获取待审核照片列表
```
GET /api/admin/photos/pending
```
**响应**：返回所有待审核的照片列表（包含相册信息、上传者信息）

#### 4.1.2 获取所有照片列表（管理员视图）
```
GET /api/admin/photos
```
**查询参数**：
- status: pending/approved/rejected（可选，筛选状态）
- page: 页码（默认1）
- size: 每页数量（默认20）

**响应**：返回分页的照片列表

#### 4.1.3 审核通过照片
```
POST /api/admin/photos/{id}/approve
```
**响应**：成功返回200

#### 4.1.4 审核拒绝照片
```
POST /api/admin/photos/{id}/reject
```
**请求体**：
```json
{
  "reason": "拒绝原因（可选）"
}
```
**响应**：成功返回200

#### 4.1.5 批量审核通过
```
POST /api/admin/photos/batch-approve
```
**请求体**：
```json
{
  "photoIds": ["id1", "id2", "id3"]
}
```
**响应**：成功返回200

#### 4.1.6 批量审核拒绝
```
POST /api/admin/photos/batch-reject
```
**请求体**：
```json
{
  "photoIds": ["id1", "id2", "id3"],
  "reason": "拒绝原因（可选）"
}
```
**响应**：成功返回200

### 4.2 修改现有接口

#### 4.2.1 照片上传接口
修改 `POST /api/albums/{albumId}/photos`：
- 普通用户上传的照片状态为 `pending`
- 管理员上传的照片状态为 `approved`

#### 4.2.2 照片列表接口
修改 `GET /api/albums/{albumId}/photos`：
- 普通用户只能看到 `approved` 状态的照片
- 管理员可以看到所有状态的照片（可通过参数筛选）

## 六、业务流程

### 6.1 照片上传流程

```
用户上传照片
    ↓
保存到存储（七牛云/本地）
    ↓
写入数据库（status=pending）
    ↓
照片进入待审核队列
```

### 6.2 照片审核流程

```
管理员进入审核页面
    ↓
查看待审核照片列表
    ↓
选择照片进行预览
    ↓
点击"通过"或"拒绝"
    ↓
更新数据库状态
    ↓
照片状态变更完成
```

### 6.3 照片展示流程

**普通用户查看相册**：
```
请求照片列表
    ↓
后端过滤：只返回 status=approved 的照片
    ↓
前端展示照片
```

**管理员查看相册**：
```
请求照片列表
    ↓
后端返回所有照片（包含各状态）
    ↓
前端根据状态显示不同标识
```
